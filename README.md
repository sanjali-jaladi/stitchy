# stitchy

A minimal, keyboard-first word game. You're shown a few letters, like `R  A  E`.
Type a real English word that contains all of them, in any order and any position
(**wa**t**er**, g**r**e**a**t, **ar**ena). Find as many as you can in **120 seconds**.

```sh
npm install
npm run dev      # http://localhost:5173
npm test         # unit tests (vitest)
npm run build    # type-check + production build into dist/
```

## How to play

The home screen lists the variations. Pick one with `↑`/`↓` and `enter`, the shortcut
keys `2` `3` `4` `c`, or a click or tap. The next screen shows how long the game lasts.
Press `enter` (or tap, on a phone) to start the 120-second clock. The first letters
appear when the clock starts.

| mode    | letters per set     | shown as  |
| ------- | ------------------- | --------- |
| `2`     | 2                   | a line    |
| `3`     | 3                   | a triangle |
| `4`     | 4                   | a square  |
| `combo` | 2, 3 or 4 at random | per set   |

A word counts only if **all** of these are true:

1. It's spelled correctly, exactly as it appears in the dictionary. There's no autocorrect, fuzzy matching or partial credit.
2. It contains every shown letter. A letter shown twice (`E  E`) must appear at least twice.
3. It's longer than the set, so the letters on their own don't count.
4. You haven't used it yet this game.

| screen  | keys                                                                      |
| ------- | ------------------------------------------------------------------------- |
| home    | `↑` `↓` choose · `enter` select · `2` `3` `4` `c` jump straight to a mode |
| ready   | `enter` start · `esc` back to home                                        |
| playing | `enter` submit · `tab` skip (costs 2 seconds) · `esc` restart             |
| results | `enter` or `tab` play again · `esc` home                                  |

Clicking the `stitchy` wordmark also goes back to home.

The footer hints are also tappable, so the game works on phones without a tab key.

**Counting:** there are no points. Every valid word counts as one, whatever its
length, and the count sits at the top right while you play.

**Timing:** each set's clock runs from when it appears until you enter a valid word,
so rejected attempts count toward that time. Skipped sets don't count toward the timing stats.

The results screen shows words, longest and shortest word, fastest and slowest, a
small bar chart of how many words had each length, your
personal best (most words) for the mode, and every set you saw. For skipped sets it
also shows example answers. The theme is light by default; the footer button (labelled with
the other theme) switches between them. Personal bests and the theme are stored
in `localStorage`. The game still works if storage is unavailable.

## Word lists

Both lists come from **SCOWL** (Spell Checker Oriented Word Lists) by Kevin Atkinson,
via the [`wordlist-english`](https://github.com/jacksonrayhamilton/wordlist-english)
npm package. They're generated by `npm run words` (`scripts/build-words.mjs`) and
committed in `public/`:

- `public/dictionary.txt` (~115k words) is used **only to validate spelling**. It
  contains every SCOWL word up to size 70 in the English, American, British,
  Canadian and Australian variants. Proper nouns, abbreviations, and words with
  accents or apostrophes are removed.
- `public/common.txt` (~11k words) is used **to generate letter sets** and example
  answers. It contains SCOWL sizes 10 and 20 (the most common words), with the
  same filtering and a minimum length of 3.

Both files load asynchronously at startup and are looked up from a `Set`.

**License:** SCOWL is free to use, copy, modify, distribute and sell, provided its
copyright and permission notice is included. The full notice is in
[`public/WORDLIST-LICENSE.txt`](public/WORDLIST-LICENSE.txt). It also covers SCOWL's
public-domain sources (Moby Words II, 12Dicts and others). `wordlist-english` itself
is MIT licensed.

## How letter sets are generated

1. Pick a random common word and sample 2–4 of its letters (repeats are possible, e.g. `N N T`).
2. Keep the set only if enough common words longer than the set contain all of its
   letters: at least **30** for 2 letters, **15** for 3 and **8** for 4. Otherwise resample.
3. Sets made only of vowels and S (like `E  A`) are usually rejected (85% of the time).
   This weights the game toward sets with a real consonant.
4. Never repeat a set within a game. Letters are shuffled and spaced out so they read
   as a set rather than as a piece of a word.

## Code layout

```
src/game/      pure, framework-free logic (unit tested)
  letters.ts     letter multisets, matching, highlighting
  dictionary.ts  word-list parsing and loading
  validate.ts    the four validity rules and rejection messages
  generator.ts   solvable letter-set generation
  session.ts     one 120s game: clock, skips, per-word timing, records
  stats.ts       results (fastest/slowest/longest/shortest)
  storage.ts     guarded localStorage
src/main.ts    DOM wiring
src/style.css  themes (CSS variables), layout, motion
test/          vitest suites
```

## Deploy to GitHub Pages

The site deploys automatically via [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)
whenever you push to `main` (you can also run it by hand from the Actions tab).
Each run tests, builds, and publishes `dist/`. One-time setup: in the repo go to
**Settings → Pages** and set **Source** to **GitHub Actions**. The site is then served at
`https://<username>.github.io/<repo>/`.
